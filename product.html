The gap

Valid is not the same as admissible.

Authorization answers one question: was this allowed when we checked? Agents act later, on cached approvals. In between, a policy rotates, a session is revoked, a trust score moves, an upstream source goes bad. The tool itself did not change, so nothing asks again. That window is a vulnerability class of its own: time of cache to time of use.

Security already has boundaries at the network, the identity and the device. TSPM adds one at the cache: the point where a stored approval is about to be used.

Where this came from

It started with one bug in Lockdown Mode.

In 2025, founder Stanley Lee Linton reported to Apple that cached WebAssembly kept executing in Safari after Lockdown Mode was switched on. The code had been approved under the old policy, and nothing asked again.

Apple credited the report in its iOS 26 and iPadOS 26 security notes. The same pattern turns up wherever a stored approval outlives the conditions that justified it. STAAML named the class, generalized the mitigation and built TSPM Gateway on it.
